# Contributor guide

## Project purpose and capabilities

The project's purpose is to provide a legacy-state migration path for Apache Flink jobs using Avro. With Flink's regular Avro serializer, a schema change such as adding or removing a field can require migration and rewrite of the entire state, potentially taking hours for large state. This serializer instead resolves each record's writer schema at read time and projects it to the current reader schema, avoiding an eager full-state rewrite for compatible changes. This follows the same broad pattern used by data lakes, where old records are projected to a reader schema rather than rewriting all historical data after every schema change.

The implementation provides an Apache Flink `TypeSerializer` for Avro `GenericRecord` and generated `SpecificRecord` state. New state defaults to empty frame magic. Every written record is framed as frame magic, a format version byte, the Schema Registry ID of its writer schema as a varint, and the Avro datum; null is rejected like Flink's regular Avro serializer does. On restore, the Registry resolves the writer schema and Avro projects the value onto the reader schema configured by the current job.

The serializer also supports a transition from Flink's regular Avro serializer: it reads the old `AvroSerializerSnapshot` to obtain the single legacy writer schema, reads those raw Avro values in place, and writes subsequent updates in framed format. Legacy and framed values may coexist in state. Raw legacy values have no header and use Flink's `DataOutputEncoder` layout (4-byte big-endian int/float/enum/union index, 8-byte long/double, 4-byte length before strings and bytes, varint array/map counts), not Avro binary encoding. `LegacyFrameAnalysis` replays every byte sequence that layout can produce for the legacy writer schema against a candidate magic and reports whether a legacy value can begin with the whole magic (collision) or end before it (over-read). It derives the shortest impossible all-`FF` prefix from the schema encoding (up to eight bytes), returns incompatible when no proven safe magic is available. Set `use.unsafe.magic=true` to allow the six-byte `SRAVRO` fallback or a colliding explicit magic only when it cannot over-read; set `allow.full.migration=true` to permit a full legacy rewrite when no magic is accepted. The choice is logged, `frame.magic` overrides the automatic choice (collisions require explicit unsafe opt-in; over-read is always refused), and the magic is persisted in the snapshot. A test pins the encoder layout the walker models. Do not claim support for multiple legacy writer schemas from one previous snapshot or for arbitrary serializer migrations.

The serializer snapshot version is 1. It records the record kind and, for SpecificRecord, the record class name, plus the frame magic, whether legacy values can be shorter than it, the Registry subject, any legacy raw-Avro schema and the last completed force-migration nonce. It does not persist a GenericRecord schema: each Confluent-framed value resolves its writer schema from its own schema ID. The subject is retained for restore-time compatibility verification; Schema Registry client configuration remains a current-runtime setting, not snapshot data. `restoreSerializer()` eagerly creates a read-only historical serializer: GenericRecord reads resolve each stored event's writer schema and read using that schema, while SpecificRecord reads load the named class from the current user-code classloader and use that class's current schema. Registry client settings for this historical reader come from Flink global configuration.

For a newly selected force-migration nonce, the current writer rewrites state. SpecificRecord decoding already targets the current runtime class/schema. GenericRecord decoding uses its historical schema, so while migration is pending the current serializer checks the schema only on writes and projects old-schema records to the current schema before writing. This extra comparison/projection path is limited to GenericRecord forced migration.

When there is no legacy raw-Avro schema to carry forward and the frame magic is unchanged, serializer snapshot changes are Flink-compatible-as-is; when a legacy schema or a different persisted magic is present they are preserved via a reconfigured serializer. Before any of that, `resolveSchemaCompatibility` verifies (unless `verify.schema.compatibility` is false) that the current reader schema can read the legacy schema and every schema recorded as potentially present in state, and registers the reader schema, so an incompatible evolution or a Registry rejection fails the restore rather than a later state read. Registry operations use Confluent's Schema Registry client and may perform network calls during restore and state serialization/deserialization.

## Build and test

Use the Gradle Wrapper:

```powershell
./gradlew check
./gradlew check -PjavaVersion=21 '-PflinkVersion=2.2.1'
```

Quote `-PflinkVersion=...` in PowerShell. Defaults are Java 17 and Flink 2.3.0. CI tests all Java 17/21 and Flink 2.2.1/2.3.0 combinations.

Tests include unit coverage for framing, null rejection, copies, legacy reads (including values shorter than the old probe and consecutive values in one stream), frame magic selection from legacy schemas, restore-time compatibility verification, snapshot compatibility, nested Avro schema projection and forced migration, and authenticated Schema Registry client requests using environment- and file-based secrets. RocksDB-backed MiniCluster savepoint tests cover GenericRecord and generated SpecificRecord restore. GenericRecord has no schema in its Java class: use `GenericRecordAvroTypeInfo(schema)` when testing Flink's regular Avro serializer. Keep the test's Kryo/generic fallback disabled so a missing Avro type-information setup fails rather than silently exercising Kryo. Do not replace inferred SpecificRecord Avro type information or schema-aware GenericRecord type information with an explicit `AvroSerializer` in fallback/migration tests; those tests verify Flink's default behavior.

Keep OS detection and platform-specific test temporary paths in Gradle's `Test` task configuration. Java tests should read the configured paths from system properties and should not branch on `os.name`. Set test environment variables such as `FLINK_CONF_DIR` in Gradle rather than changing the process environment from Java tests.

## Implementation rules

- Compile against Flink as `compileOnly`; the consuming Flink distribution provides it at runtime.
- Keep the Confluent Schema Registry client dependency `compileOnly`; consuming jobs choose a compatible client version at runtime. Do not add a dependency on Confluent Kafka Avro serializer/deserializer classes. Avro is part of the published API.
- Use the configured subject literally for schema registration and ID lookup. Schema IDs, not subjects, select writer schemas during reads.
- The public factory map is named `serializerConfig`. Retain only `schema.registry.url`, `auto.register.schemas`, `normalize.schemas`, `max.schemas.per.subject`, `frame.magic`, `verify.schema.compatibility`, `allow.full.migration`, `use.unsafe.magic`, and optional `force.migration.nonce`; log and ignore other map keys. `force.migration.nonce` can also be set in Flink global config as `schema.resolving.avro.force.migration.nonce`; the map value takes priority. For duplicate Registry client settings, `serializerConfig` takes priority and Flink global config under `schema.resolving.avro.*` supplies missing values. Keep credentials out of the serialized config map.
- All full rewrites require `allow.full.migration=true` in `serializerConfig` (default false); otherwise return incompatible and log how to enable migration. This includes nonce, frame magic changes, and unsafe legacy migration policy.
- An integer `force.migration.nonce` requests compatible-after-migration for supported Confluent and regular Flink Avro state when it differs from the nonce recorded in the previous snapshot. Persist the new nonce in snapshot version 1 so a restart with the same nonce does not repeat the rewrite. A different nonce requests another migration.
- Resolve runtime Registry client settings from `serializerConfig` first, then fill missing settings from Flink global config under `schema.resolving.avro.*`. Secret references use `schema.resolving.avro.secret.<client-property>.env` or `.file`, exactly one source per client property. Read secrets at client creation, trim file contents, and never persist or log resolved values.
- Implement value reuse by passing the supplied record to Avro `DatumReader.read(reuse, decoder)` for both framed values and legacy raw Avro values. Cache datum readers per writer schema ID, datum writers and schema IDs per writer schema, and reuse the Flink decoder/encoder; a serializer instance is single-threaded and `duplicate()` gives each thread its own caches.
- Analyze minimum legacy value size once when bridging legacy state and persist whether values can be shorter than the magic. Bulk-read the magic only when no legacy value can be shorter; otherwise probe one byte at a time. Replay consumed bytes to the legacy reader on mismatch; never read past a value. Frame values without a length prefix; `copy(DataInputView, DataOutputView)` is `serialize(deserialize(source), target)` and must never re-encode by field position with another schema.
- Record the effective migration nonce (serializer map first, then Flink global config) in the snapshot, so a nonce set only in Flink config on a fresh job does not trigger a rewrite at the first restart.
- Keep the serializer snapshot version at 1. Review snapshot payload changes for compatibility; this project has not been deployed, so the v1 payload may evolve before release. Any wire-format change requires an explicit snapshot/version compatibility review.
- Never serialize Schema Registry credentials into a serializer or snapshot. Reject secret-bearing config keys and keep runtime credentials external to the serializer's serializable config map.
- Keep serializer and snapshot behavior deterministic and test binary compatibility, null handling, schema projection, copies, legacy raw-Avro bridging, and savepoint restoration.
- Do not commit credentials or signing keys.

## Publishing

Coordinates are `io.github.gliter:schema-resolving-avro-serializer`, with release artifact versions in the format `major.minor.patch-<Flink version>`. Local Gradle builds use the same version with a `-SNAPSHOT` suffix. Use `centralBundle` to create the signed archive consumed by the tag-driven release workflow. Release tags contain only the library version, such as `v1.2.3`; the workflow validates the tag format, uses its version for each supported Flink artifact, and creates a GitHub Release after Central accepts both uploads. Central validation and publishing continue asynchronously.

Writer schema history is stored as `SchemaInfo(subject, version, schemaId)` entries. Initialization records the configured runtime schema; lazy restores preserve all previous entries, including previous subjects. Compatibility checks resolve recorded IDs rather than scanning Registry history. Full rewrites reset the list to the current writer. DEBUG logs list entries; INFO logs show distinct candidate-version counts per subject. Normal GenericRecord writes must use the configured schema; forced migration projects historical records before writing.
